XMR Miner Setup

Moving the Monero miner from the M2 to your M4. Both machines mine to the same wallet.

Payout wallet — same on both Macs
wallet.local — public receive address only (not in git)

✓ Copy wallet.local.example to wallet.local and put the public Monero receive address there. Spend and view keys never belong in this folder.

01

Get the files across

  1. Copy the package to the M4

    AirDrop XMR-Miner-Portable.zip from this Mac's Desktop. A USB drive or iCloud Drive works just as well.

  2. Unzip it

    Double-click the zip. You get a folder called XMR MINER under Desktop/PROJECTS. That folder is the install.

02

Install

  1. Open Terminal on the M4

    Applications → Utilities → Terminal.

  2. Run the installer

    Type cd (with a space), drag the XMR MINER folder onto the Terminal window, press Return. Then:

    ./install.sh

  3. Check what it reports, then confirm

    It prints the chip, core count, memory, and the worker name it picked, then asks Proceed? [y/N]. Type y and Return.

    It writes a launchd job with this Mac's paths and core count, and builds XMR Miner.app in this folder. It starts nothing.

If macOS refuses to run it

Files picked up a quarantine flag in transit. Clear it and retry:

xattr -dr com.apple.quarantine "/Users/christiantavarez/Desktop/PROJECTS/XMR MINER"
03

Start mining

  1. Double-click XMR Miner.app in this folder

    Orange Monero icon. It asks whether to start. Click Start Mining.

  2. Wait about a minute, then click it again

    It needs that long to build its 2 GB dataset and reach full speed. Clicking again shows speed, uptime, shares, and a Stop button.

What good looks like

Shares accepted climbing, rejected staying at 0. That is the pool confirming your work. Speed on an M4 should beat the M2's ~3,200 H/s, partly from the faster chip and partly because 16 GB+ means the dataset is never squeezed.

04

Confirm both Macs are paying you

Open your MoneroOcean dashboard and paste the wallet address above. You should see two workers reporting:

MachineWorker nameWallet
This M2minerv3-m2-8gbsame
Your M4minerv3-m4-…gbsame
Why the names differ

Deliberate. The wallet is what gets paid; the worker name only labels which machine did the work, so you can see each one's speed separately. Two machines with the same worker name would have their stats merged and be impossible to tell apart. Payouts combine either way.

05

Tune it (optional, ~10 minutes)

The installer sets threads to the M4's core count. That was the right answer on the M2 when measured — but it is a sensible default, not a measurement, and the M4 has a different fast/efficiency core split. To get the real number:

"/Users/christiantavarez/Desktop/PROJECTS/XMR MINER/bin/xmr_bench_sweep.sh"

Stop the miner first. It mines nothing while testing. For reference, the M2 climbed steadily and peaked exactly at its core count:

Threads45678910
H/s2185255828383093321231633092

If a different count wins on the M4, edit both --threads and --randomx-init in:

/Users/christiantavarez/Desktop/PROJECTS/XMR MINER/com.minerv3.xmrig.plist

Then stop and start from the app.

After a restart

Mining stays off until you click the app. That is intentional — nothing launches at login. If it crashes while running, macOS restarts it on its own within 30 seconds.

07

Three rules worth keeping

Never run two miners on one Mac

They fight over the same cores and each grabs its own 2 GB dataset. Measured on the M2: 3,100 H/s collapsed to 240. The app and the installer both refuse if one is already running — don't work around it. Two separate Macs is completely fine, which is the whole point here.

Never move the miner into Downloads or Desktop

macOS protects those folders. The background job has no permission for them and no way to ask, so it freezes on startup with no error message at all — it looks alive but does nothing. This cost an hour to diagnose on the M2. The installer puts everything in Application Support for exactly this reason. Leave it there.

Free memory is what sets your speed

The miner must keep a 2 GB dataset in RAM. If the Mac runs low, macOS compresses part of it and speed collapses — this is almost always the cause of a sudden drop, not a busy CPU. The M2 lost about 8% to this constantly on 8 GB. An M4 with 16 GB+ should be fine, but if speed dips, close apps before changing any settings.

08

If something looks wrong

SymptomLikely causeFix
App says running, speed stays 0 Still building the dataset Wait 60 seconds, click again
Rejected shares climbing Clock drift or a flaky connection Check the Mac's date & time is set automatically
Started but nothing happens, no logs Installed into a protected folder Re-run install.sh; don't relocate it afterwards
"Already running" but nothing visible A stray copy from a previous attempt pkill -x xmrig then start from the app
Speed much lower than expected Memory pressure, or thread count Close apps first; then run the sweep in step 05
—

One thing that is not in the package

Your wallet keys. The package carries only the public receiving address, which is all a miner needs. The keys never left the M2 and are not required to mine — keep them where they are, and keep a backup somewhere safe that is not a mining machine.
