Memory footer · 3 designs

A small, always-there readout of the Mac's memory at the bottom of XMR Miner. The question it answers for mining: is there room for the 2.3 GB RandomX dataset, and is macOS squeezing it (compressing or swapping), which slows the hash rate. Each window below is the real miner UI rendered by its own code with the design switched on; only the numbers in the two example states are made up.

What is real here. Every frame is miner-ui.py --dump from a copy of today's miner (release d6b6d93) with the design's code added: the ledger, rail, key bar and colours are the app's own. The Now numbers were measured on this M4 when the page was built (sysctl, vm_stat, ps; "free" counted the way Agentic Coder's footer does: free + inactive + speculative + purgeable). Mining with room and 8 GB Mac, tight are example numbers, to show the other states; the miner shown in them is the UI's demo (4,178 H/s).

Thresholds used (the same in all three): fine = normal pressure and at least 0.75 GB spare beyond the dataset; tight = pressure level 2, or less spare than that; squeezed = critical pressure or under 0.5 GB free. The live footer would refresh every 5 seconds.
